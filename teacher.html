Teacher Guide · Avionics Academy

Mission 02 · PAPIMission 03 · Stall warningMission 04 · Radar altimeter

Learners are 15, they would rather not do electronics, and they must still learn it. The plan: win first, build second. They play PAPI Pilot (20 min) so the lights already mean something. Then they build the same lights in Tinkercad (40 min) and check the circuit against the game. Every answer is here.

Setting up the room (all missions)

  • Open the hub on each device, add one player per student, and tap a name before they play. Progress is saved in that browser only.
  • Pairs work best: one plays (or builds), one reads the HUD/Serial numbers aloud, then swap each mission.
  • Each student needs a free Tinkercad account (tinkercad.com, “Circuits”). If you cannot sign up in class, create a class and share the join code.
  • Suggested 90 min: 5 min hook · 20 min PAPI Pilot (missions 1–3) · 40 min Tinkercad build · 10 min test it and Wire Doctor · 10 min Test Arena quiz · 5 min review.
  • Hook line: “Pilots land in the dark with no instruments but four lights. Today you play the pilot, then you become the electrician who builds them.”

Tinkercad build: why every connection exists (teacher notes)

ConnectionWhy (say it in teenager)
Arduino 5V → + rail, GND → − railEvery circuit is a loop. The rails are a motorway so every part can join.
Pot terminals → 5V and GNDThe track needs 5 V at one end and 0 V at the other, otherwise the wiper has nothing to divide.
Pot wiper → A0The wiper voltage is the “angle”. A0 is the only kind of pin that measures voltage.
Pin → resistor → LED anodeThe pin pushes 5 V out. The resistor stops too much current from killing the LED. The anode is the “in” leg.
LED cathode → − railCurrent must be able to leave, or the loop is broken and the LED stays dark.
Resistor straddles the middle gapThe two halves of the breadboard are not connected. The resistor is the bridge.
White on even pins, red on oddRegular pattern means arrays and one for-loop control all 8 LEDs.

Quick quiz (from the notes)

  1. What does a pilot see when they are well below the glide slope?
    Mostly or all red lights (“red on red, you’re dead”). They are too low and must climb.
  2. A potentiometer wiper reads 2.5 V. What does analogRead return?
    About 512 (half of 1023).
  3. Why do we put the pin numbers in arrays?
    So a for-loop can control all four units with the same code. White pins are always even (2, 4, 6, 8) and red pins odd (3, 5, 7, 9).

Theory: how high should I be?

height = distance × tan 3° (tan 3° = 0.0524)
3 km: 3000 × 0.0524 ≈ 157 m
1 km: 1000 × 0.0524 ≈ 52 m
500 m: 500 × 0.0524 ≈ 26 m
Pilot’s rule of thumb: ≈ 300 ft per nautical mile (gives the same answer).
ADC resolution: 6° ÷ 1023 ≈ 0.006° per step, much finer than the 0.33° gap between units.

Test Arena (Mission 02 test)

15 questions. Full explanations show after each answer, so no separate key is needed. Correct options are: p-adc “About 512”, p-trig “About 157 m”.

Questions to ask while they play / build

  1. Why does one LED of each unit need to be OFF when the other is ON?
    A PAPI unit shows one colour at a time: above its angle = white, below = red. The code writes the opposite value to the red pin.
  2. Why do the units change one at a time, and which goes first as the angle rises?
    Each has its own angle. Unit 4 (2.50°) turns white first, then unit 3, 2 and 1.
  3. What happens at 3.00° and at 3.40°?
    3.00°: 2 white (ON SLOPE). 3.40°: 3 white (SLIGHTLY HIGH).
  4. Why not 4 identical angles?
    Then all four would flip at once; the spacing gives a graded warning, so the pilot knows how far off the slope they are.
  5. Before Trig Check: what height at 1 km?
    52 m (not 157 m).

Boss level solutions

Boss 1 · Buzzer. Add a Piezo: one pin to D10, the other to GND. Delete delay(200); at the end of loop() and replace it with:

const int BUZZER = 10;        // put this near the top
// in setup(): pinMode(BUZZER, OUTPUT);

// at the end of loop(), instead of delay(200):
float error = abs(angle - 3.0);                 // how far from the slope
if (error < 0.17) {
  noTone(BUZZER);                               // on slope: silence
  delay(200);
} else {
  int gap = map(constrain(error * 100, 17, 300), 17, 300, 500, 60);  // far = fast beeps
  tone(BUZZER, 880, 40);
  delay(gap);
}

Checks: on slope is silent; at 0° or 6° the beeps are fast. The further from 3°, the shorter the delay.

Boss 2 · map() and whole numbers (tenths of a degree).

const int UNIT_TENTHS[4] = {35, 32, 28, 25};    // 3.5, 3.2, 2.8, 2.5 degrees
// in loop():
int raw = analogRead(GLIDE_KNOB);
int tenths = map(raw, 0, 1023, 0, 60);          // 0..60 = 0.0 to 6.0 degrees
for (int i = 0; i < 4; i++) {
  bool above = tenths > UNIT_TENTHS[i];
  digitalWrite(WHITE_PIN[i], above ? HIGH : LOW);
  digitalWrite(RED_PIN[i],   above ? LOW : HIGH);
}
Serial.print(tenths / 10); Serial.print("."); Serial.println(tenths % 10);

Half way (raw 512) gives 30 tenths = 3.0°: 2 white. The thresholds are rounded to the nearest tenth, so the on-slope band is 2.9° to 3.2° in this version. That is the trade-off for using whole numbers.

Boss 3 · Height coach.

// put this in loop() after the existing prints
float distance = 1000;                                   // metres, try 3000, 1000, 500
float height = distance * tan(3.0 * PI / 180.0);          // tan works in radians
Serial.print("Correct height at "); Serial.print(distance, 0);
Serial.print(" m = "); Serial.print(height, 1); Serial.println(" m");

Prints 157.2 m at 3000 m, 52.4 m at 1000 m, 26.2 m at 500 m. Degrees × π ÷ 180 converts to radians.

Common mistakes (also in the student Wire Doctor)

  • All LEDs dark: rail not wired to GND. One LED dark: backwards. LED “explodes”: no resistor.
  • Lights never respond: wiper wire on an end terminal instead of the middle pin, or on A1.
  • Wrong colour order: white/red swapped between even/odd pins.
  • Code errors: pasted over only part of the old code. Select all first, and use Text mode, not Blocks.

Mission 03 · Stall Warning System

Hook: “Why does a plane fall out of the sky if it flies too SLOWLY and not just too low?” Play Stall Watch (25 min), then build the alarm with the Tinkercad guide (40 min).

Game: what each mission teaches

MissionConcept from the notesWhat the student does
Stall Watch · 1 Find the Critical AngleAoA, lift rises about 0.1 CL per degree to about 15°, then collapsesRaises the angle slowly, sees CAUTION at 12°, STALL at 15°, recovers below 12°.
Stall Watch · 2 Slow FlightL = ½ρv²S·CL: slower needs more angle; stall speedHolds altitude while the speed drops and flies 3 s in the 12–15° caution band.
Stall Watch · 3 Tune the Hornf = 1 ÷ T, λ = v ÷ f, higher frequency = higher pitchCalculates and dials in 1000 Hz, 800 Hz (λ 43 cm) and 2000 Hz (λ 17 cm).
Stall Watch · 4 Rig the Warning Logicif / else if / else, order of checksOrders three checks; a wrong order hides the stall horn and fails the test flight.
Stall Watch · 5 Stall RecoveryRecovery = lower the angle of attack; do not over-correctLowers the nose to about 6–10° to regain lift before reaching 100 m.

Game answers

  • Critical angle: 15° (CL max ≈ 1.5). After that CL drops sharply.
  • Level flight angle: 60 m/s → 2.8°; 45 m/s → 4.9°; 30 m/s → 11.1°; 27 m/s → 13.7°. Stall speed (weight 9810 N, S = 16 m², ρ = 1.225, CL max 1.5): √(9810 ÷ (0.5 × 1.225 × 16 × 1.5)) ≈ 26 m/s.
  • Tune the horn: T = 1 ms → f = 1000 Hz. λ = 43 cm → f = 343 ÷ 0.43 ≈ 800 Hz. λ = 17 cm → f = 343 ÷ 0.17 ≈ 2000 Hz (T = 0.5 ms).
  • Warning logic order: (1) aoa ≥ STALL_AOA, (2) else if aoa ≥ CAUTION_AOA, (3) else. Reason: 16° satisfies both conditions and only the first true branch runs.
  • Recovery: lower the angle of attack to about 6° to 10°. 0° gives almost no lift, so you dive.

Quick quiz (from the notes)

  1. What is the angle of attack?
    The angle between the wing and the oncoming air (not the nose above the horizon).
  2. Why is the stall check written before the caution check?
    Because an angle that is a stall (≥ 15°) is also ≥ 12°. In an else-if chain the first true condition wins, so the more serious one must be first.
  3. What does a higher tone() frequency sound like?
    A higher pitch.

Theory: CL is about 0.1 per degree, so 12° ≈ 1.2 and 15° ≈ 1.5. f = 1 ÷ T: at 2000 Hz T = 0.0005 s = 0.5 ms, wavelength λ = 343 ÷ 2000 ≈ 17 cm. At 800 Hz T = 1.25 ms and λ ≈ 43 cm.

Questions to ask while they play / build

  1. A plane can stall at any speed or attitude. Why?
    Stall depends only on angle of attack. Too much angle at any speed breaks the airflow away.
  2. Why does the caution begin at 12° and not 15°?
    To give the pilot time to react before the cliff edge.
  3. If we swap the order and check 12° first, what happens at 17°?
    Caution is true first, so only yellow + beep: the stall horn never sounds. Dangerous!

Boss level solutions

Boss 1 · Faster beeps (replace the delay(400); inside the caution branch):

int gap = map((int)(aoa * 10), 120, 150, 400, 100);   // 12 deg = slow, 15 deg = fast
tone(BUZZER, 800, 60);
delay(gap);

Boss 2 · Stick shaker (servo to D9, power to 5V, ground to GND):

#include <Servo.h>
Servo shaker;                      // global

for (int i = 0; i < 3; i++) {
  shaker.write(70);  delay(40);

Any order works for this branch because −3° does not overlap with the other two conditions.

Mission 04 · Radar Altimeter Display

Hook: “How does a plane know it is exactly 9 m above the ground in the fog?” Play Radar Altimeter (25 min), then build the display with the Tinkercad guide (60 min). This is the hardest wiring so far, so run it in pairs and use the Wire Doctor.

Game answers

  • 5830 µs: 0.0343 × 5830 = 200 cm there and back → 100 cm. 11 660 µs → 200 cm. 2915 µs → 50 cm.
  • 35 °C: v = 331 + 0.6 × 35 = 352 m/s = 0.0352 cm/µs. A 0.0343 sensor reads 200 × 343 ÷ 352 ≈ 195 cm (about 2.6% low).
  • 5 °C: v = 331 + 0.6 × 5 = 334 m/s = 0.0334 cm/µs. A 0.0343 sensor reads about 154 cm for a true 150 cm (high).
  • Descent rate: (248 − 233) ÷ 0.5 = 30 cm/s. The target window is 25 to 45 cm/s.
  • Flare: wait for FLARE NOW! (below 50 cm), hold Space, touch down at or below 30 cm/s. Flaring above 60 cm is “too early”.

Quick quiz (from the notes)

  1. Why do we divide by 2 in the distance formula?
    The sound travels down AND back up, so the echo time covers twice the height.
  2. What does the LCD’s V0 pin control?
    The contrast (how dark the characters are).
  3. Why do aircraft use radio waves rather than sound for this?
    Radio travels at 300 000 000 m/s, nearly a million times faster, so echoes come back in microseconds even from 2500 ft, and the speed does not depend on air temperature. Sound from 2500 ft (762 m) would take 2 × 762 ÷ 343 ≈ 4.4 s for the round trip; radio takes about 5 µs.

Questions to ask while they play / build

  1. Why is the echo time 5830 µs for a 100 cm height and not 2915 µs?
    5830 µs is the round trip (200 cm of travel). The one-way time is 2915 µs.
  2. If the sensor reads low on a hot day, is the aircraft closer or farther than it says?
    Farther. Sound returns sooner on a hot day, so the Arduino thinks the ground is nearer than it is.
  3. Why print spaces after the text on the LCD?
    The LCD does not clear itself. Spaces wipe leftover characters from a previous longer message.

Boss level solutions

Boss 1 · Parking sensor. Piezo + to D8, − to GND, pinMode(8, OUTPUT) in setup. Replace delay(200); at the end of loop():

if (alt > 0 && alt < APPROACH_CM) {
  tone(8, 1000, 40);
  delay(map(alt, 2, APPROACH_CM, 50, 500));   // closer = faster beeps
} else {
  noTone(8);
  delay(200);
}

Boss 2 · Feet. Replace the alt printing with:

lcd.print("ALT ");
lcd.print(alt / 30.48, 1);        // 1 ft = 30.48 cm, one decimal
lcd.print(" ft      ");

Check: 100 cm → 3.3 ft. 30 ft ≈ 914 cm, which is where a real flare would start.

Boss 3 · Descent rate.

long lastAlt = 0;                  // globals
unsigned long lastTime = 0;
// in loop(), after reading alt:
unsigned long now = millis();
float rate = (lastAlt - alt) * 1000.0 / (now - lastTime);   // cm/s, positive = descending
lastAlt = alt;  lastTime = now;
lcd.setCursor(9, 0);
lcd.print((int)rate);
lcd.print("cm/s  ");

The row-0 text “ALT 87 cm” takes 9 characters, so the rate starts at column 9. Time is measured with millis() so the answer stays right even though the loop is not exactly 200 ms.

Out of range: the Tinkercad sensor works from about 2 to 330 cm. Beyond that pulseIn() times out and returns 0, so the LCD shows 0 cm and FLARE NOW!. Tell students to keep the target in range.
